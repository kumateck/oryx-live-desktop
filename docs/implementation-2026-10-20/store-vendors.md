# Store vendors — 2026-10-21

`/extrals/vendors` now uses a protected module manifest and the existing generated inventory API. The register retains pagination, full contact fields, country/currency and every supplied inventory item. Detail/create/edit/delete use the shared dialog, FormWizard and action components. Read response validation rejects incomplete identities instead of allowing writes against guessed IDs.

The server vendor list ignores `searchQuery`. Live's debounced search reads every page, verifies stable pagination and identity, and filters the complete register by name/email/contact/telephone. Failed or moving pages produce an error instead of partial results. Search is bounded to 20,000 records. Normal unfiltered lists remain server-paged.

Vendor authoring retains name, contact person, telephone, email, full address, country, currency and every selected item. The store selector only scopes item search; changing stores does not clear existing associations. This preserves cross-store vendors and numeric IT-store zero. Newly selected items require active status and the exact existing per-store read key; existing associations can remain unchanged during a contact-only edit. Country/currency are revalidated against the existing collection contract. Fresh vendor evidence, current action permission, newly required store permissions and signed-in account identity are checked before mutation. Sent changes cannot be repeated from the same editor after a refused or ambiguous response.

Exact keys: `CanViewVendors`, `CanCreateVendor`, `CanUpdateVendorDetails`, `CanDeleteVendor`; item search uses the existing CanViewItemsInItStore/GeneralStore/EquipmentStore/ReagentStore keys. No administrator bypass or invented key is added. All writes send General Stores/Vendors audit headers and retain generated cache invalidation; complete search results use the same vendor list tag.

Server limitations remain explicit: vendor CRUD currently has only authenticated backend access, with no per-operation permission attributes; vendor-by-item and item listing allow anonymous reads. Client guards do not repair this server authorization gap. Update also lacks duplicate name/email enforcement, and soft deletion does not validate linked procurement records. No backend vendor contract or authorization repair has been applied during this stage.

Verification: seven focused vendor tests cover all-page search, failure without partial results, multi-store defaults, duplicate/missing field validation, stale evidence, retained associations on contact edits and 409 without replay. Combined with route access/coverage checks, 306 tests pass. Web TypeScript and the production build pass after fixing exact-optional store query typing. All mutations were mocked; no real vendor was created, changed or deleted.

This is one of the general stores/services reference routes. Service/provider workflows are covered in services-and-contractors.md. The remaining inventory, stock, procurement and job workflows are still pending; the five-domain request is not complete. Documentation updated: this file, implementation README/scope.csv, services.md and workflows.md.
